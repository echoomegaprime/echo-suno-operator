# Incident record: Echo Suno generation failure and insecure route

## Impact

The connected operator could not generate or reliably report provider failures. Calls surfaced `Deriving bits failed` or an earlier 422 at `/api/generate/v2-web/`. During diagnosis, the canonical connector path was also found to fall through to a stale MCP catch-all. A temporary direct origin route proved the repaired backend but exposed authenticated account status without OAuth, so it was immediately rolled back.

## Root cause chain

1. The Suno web client contract had changed: the Studio hostname, Clerk token version metadata, available model, billing plan identifier, create-surface metadata, and CAPTCHA preflight behavior were stale.
2. The MCP wrapper marked provider-recoverable results as transport errors, allowing the connector layer to collapse `CAPTCHA_REQUIRED` into a generic argument/operator failure.
3. The remotely managed Cloudflare tunnel had a dedicated Suno rule, but its path omitted the leading slash and used a wildcard-like expression instead of the required Go regular expression. Requests therefore fell through to the next generic MCP rule and reached a stale Forge service.
4. The privileged backend MCP handler had no independent shared-credential boundary, making a direct route unsafe.
5. The scheduled-task stop action terminated the wrapper but could leave its Node child running, so an apparent restart did not initially load the repaired code.

## Corrective action

The operator now resolves the current provider contract dynamically, fails closed on billing/CAPTCHA uncertainty, preserves structured CAPTCHA results, requires a runtime-only proxy credential, protects private REST data, and runs with hidden Windows launch semantics. A scoped OAuth adapter now allowlists three tools, validates scopes, proxies only to loopback, bounds exchanges, and redacts secret fields. The authoritative Cloudflare route now uses `^/oauth-mcp-suno-session-v1(/.*)?$`, targets the loopback OAuth adapter, and remains before the generic fallback. The checked-in public-boundary verifier prevents a generic HTTP 200 from being mistaken for the Suno service.

## Verification and remaining human gates

Regression tests cover provider payloads, token minting, CAPTCHA no-submit, MCP error preservation, proxy authorization, HTTP security, hidden launching, and public route ownership. Live processes run in session 0 with no window handle. After the route repair, six public discovery samples identified the scoped Suno service; an unauthenticated initialize returned HTTP 401 with an OAuth challenge and no cookie. Internal status completed in 1.2 seconds with authentication true, 2,455 credits, and `cookie_exposed: false`. The minimal generation canary returned `CAPTCHA_REQUIRED`, `submitted: false`, and no IDs. The provider CAPTCHA and one-time client connector reauthorization are human gates; neither was bypassed and the requested track was not submitted.
